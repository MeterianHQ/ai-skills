# tessl/

This directory contains tessl-specific versions of the skills for local development and publishing via the [Tessl](https://tessl.io) package manager.

## Why a separate folder

`skills/*/SKILL.md` is the single source of truth for all other agent integrations (Claude Code plugin, Windsurf, Copilot, etc.). The `tessl/` directory holds independent copies so tessl-specific improvements (metadata, LANGUAGES.md bundles, wording tuned to tessl's review rubric) can be iterated without touching the canonical skill files.

When changes here are stable, propagate them back to `skills/*/SKILL.md` and the other tool-specific files as appropriate.

## Structure

```
tessl/
  security-audit/
    SKILL.md          # tessl-optimised skill content
    tile.json         # tessl tile manifest
    evals/            # eval scenarios (generated by tessl scenario generate)
  reachability-analysis/
    SKILL.md
    SEARCH_PATTERNS.md  # import search patterns (referenced from SKILL.md)
    tile.json
```

## Local dev workflow

```bash
# After editing a SKILL.md:
tessl tile pack ./tessl/security-audit
tessl install ./local-security-audit-0.1.0.tgz
# then /reload-plugins in Claude Code

# Review quality:
tessl skill review ./tessl/security-audit

# Lint only:
tessl skill lint ./tessl/security-audit
```

Use `--watch-local` to auto-reinstall on file changes:

```bash
tessl install --watch-local ./local-security-audit-0.1.0.tgz
```

## Evals

Scenarios live in `evals/` inside each skill directory. Generate them once (or when the skill changes significantly), then run evals before publishing.

```bash
# First time: link a Tessl project to this repo
tessl project create ai-skills --workspace meterian

# Generate scenarios
tessl scenario generate ./tessl/security-audit --count 10
tessl scenario download <id> --output ./tessl/security-audit/evals/

# Run all scenarios via tessl cloud (both baseline and with-context):
tessl eval run ./tessl/security-audit --agent claude:claude-sonnet-4-6 --label "v1.0.0"
tessl eval view --last

# Run a single scenario (baseline only, no skill context):
tessl eval run ./tessl/security-audit/evals/scenario-0 \
  --agent claude:claude-sonnet-4-6 --workspace meterian
```

After every `tessl eval run`, save the full scorer reasoning to `tessl/eval-logs/<run-id>.txt`:

```bash
RUN_ID=<run-id>
tessl eval view --json $RUN_ID | python3 -c "
import json, sys
data = json.load(sys.stdin)
output = []
for s in data['data']['attributes']['scenarios']:
    output.append('=' * 80)
    output.append('SCENARIO: ' + s['task'].split('\n')[0].strip('# '))
    for sol in s['solutions']:
        output.append('')
        output.append(f'  VARIANT: {sol[\"variant\"]}')
        output.append(f'  ACTIVATED: {sol.get(\"activation\", {}).get(\"activatedSkills\", [])}')
        for r in sol['assessmentResults']:
            output.append(f'')
            output.append(f'  [{r[\"score\"]}/{r[\"max_score\"]}] {r[\"name\"]}')
            output.append(f'  REASONING: {r[\"reasoning\"]}')
    output.append('')
print('\n'.join(output))
" > ./tessl/eval-logs/${RUN_ID}.txt
```

The `tessl/eval-logs/` directory is gitignored. Name files by run ID so multiple runs are preserved.

### Running evals locally with Codex

For local iteration, use the test project at `/home/bbossola/projects/spikes/codex`, which has the skill installed and network access configured. Prerequisites:

- `~/.codex/config.toml` must have `[sandbox_workspace_write] network_access = true`
- `@meterian/cli` must be installed globally: `npm install -g @meterian/cli`
- The meterian MCP server must be removed from `~/.codex/config.toml` (to prevent Codex from bypassing the CLI via MCP tools)

Workflow for a single scenario:

```bash
# 1. Pack and install the updated skill into the test project
tessl tile pack ./tessl/security-audit
cd /home/bbossola/projects/spikes/codex && tessl install /path/to/meterian-security-audit-1.0.0.tgz

# 2. Copy scenario inputs
cp -r ./tessl/security-audit/evals/scenario-N/inputs /home/bbossola/projects/spikes/codex/

# 3. Run via codex exec
rm -f /home/bbossola/projects/spikes/codex/security-report.md
codex exec -C /home/bbossola/projects/spikes/codex --ephemeral \
  "$(cat ./tessl/security-audit/evals/scenario-N/task.md)"

# 4. Score against criteria
cat ./tessl/security-audit/evals/scenario-N/criteria.json
cat /home/bbossola/projects/spikes/codex/security-report.md
```

Note: in non-interactive (`exec`) mode, Codex skips interactive prompts (e.g. reachability offer), so the reachability mention check will always fail locally. Codex also works around the sandbox's read-only home by redirecting npm/meterian cache to `/tmp` automatically.

## Versioning

Version is tracked in each `tile.json` (`"version"` field) and mirrored in `SKILL.md` frontmatter (`metadata.version`). Keep them in sync. This is independent from the Claude Code plugin version in `.claude-plugin/plugin.json`.

## Publishing

Before publishing, ensure `tile.json` has the correct workspace (`meterian/<skill>`), `"private": false`, and the version is correct.

```bash
tessl skill publish ./tessl/security-audit

# Let tessl bump the version for future releases:
tessl skill publish ./tessl/security-audit --bump patch
```
